# v1 开发日志

技术解析见 [../articles/v1-区块存储与贪婪网格.md](../articles/v1-区块存储与贪婪网格.md)。

## 目标（开工前定的完成标准）

- 区块按 16³ section 存，每段用调色板压缩，规则和原版 `PalettedContainer` 一致
- 贪婪网格，合并前后画面完全一样（AO 不能被拉伸）
- 有纹理，并且没有版权问题
- 内存、三角形数、帧率三项对比 v0 有明显提升，有可复现的脚本

## 过程

1. **先写存储**：`BitStorage` → `PalettedContainer` → `Section` → `Chunk`。测试先行：位压缩、调色板扩容 0 → 4 → 5 → 直接模式。
   - 原版用 `long[]`，JS 没有快的 64 位整数，改用 `Uint32Array`，“值不跨整数”的规则不变。
   - 文件放进新目录 `terrain/chunk/`，import 一律写到具体文件（`./chunk/Chunk`）。
     旧的 `terrain/chunk.ts` 如果没删，`'./chunk'` 会优先解析到它。
2. **Worker 改成按 section 输出**：生成完 18×18 列的方块后，每 16 层切一段，`fromValues` 一次选好位数；
   每段展开成 18³ 邻域建网格。所有数组的底层内存转移给主线程，不复制。
3. **贪婪网格**：
   - 第一版只合并“四个角 AO 全相同”的面，四边形只降到 66.6%。
   - 加上“AO 只沿一个方向变化时，顺着不变的方向合并”，降到 58.2%，画面不变。
   - 写了一个“合并前后按方向 + 纹理统计面积必须相等”的测试，比肉眼看靠谱。
   - 第一次跑这个测试，“合并后四边形少于 80%”的断言失败：随机方块几乎没法合并。断言放宽为“少于合并前”，真实的比例看 `tools/bench-v1.ts`。
4. **纹理**：
   - 先想用纹理图集，算了一下贪婪网格的大矩形要重复铺纹理，图集做不到，换成 `DataArrayTexture`。
   - 顶点只存位置（Uint16，×16）和 `[方向, 层号, AO]`，纹理坐标在着色器里从位置算。24 字节 → 10 字节。
   - 位置放大存储后 three 自动算的包围球不对，改成写死 section 的包围球。
5. **调试工具**：F3 加内存、四边形、绘制调用；G 切换贪婪 / 逐面；K 线框。
   - 第一版线框直接把材质设成 `wireframe`，地下洞穴的线全透出来，看不清。
     改成在贴图上再叠一层黑色线框（同一个几何体，深度往前挪一点点）。
6. **挖 / 放**：重建方块周围 3×3×3 碰到的所有 section（1~8 个），AO 也正确。
7. **修 bug：从水里上不了岸**（v0 就有）。浮在水面时脚在 y≈62.7，岸边方块顶面是 63，差 0.3 格；
   身体出水后按重力下落，又没站在地面上不能跳，只能在水面上下晃。
   原版 `LivingEntity.travel` 的做法：在水中水平碰撞时把竖直速度设成 0.3 格/tick。照搬：
   `moveAndCollide` 多返回一个 `hitWall`，脚碰到水 + 撞墙 + 按着方向键 → `v.y = 6`。
   浏览器里复现：修之前游 5 秒停在岸边水底，修之后走上岸继续往前走了 10 格。

8. **v1.1：水中移动按原版重写**（v1 发布后试玩反馈）。
   - 问题：水面按住空格时上下快速抖动；水平速度是陆地速度。
     原因是 v0 的写法：脚以上 0.4 格在水里就给固定 3 格/秒上浮，出水后立刻按陆地重力（32）往下拉，
     一帧在水里一帧不在，来回切换；水平速度也是按“这一帧在不在水里”决定的，出水的那一帧就变回了陆地速度。
   - 改法：竖直速度按原版每 tick 的公式（+0.04、×0.8、-0.005）换成连续形式，平滑靠近稳定值；
     增加“游泳状态”，碰到水进入、落地才退出，期间保持水中的水平速度；水深用画出来的水面高度（14/16）算。
   - v1 的“撞墙往上蹿”补上原版的 `isFree` 条件（抬高 0.6 格后前面是空的）。
   - 实测：水面按住空格起伏 62.78 ~ 62.91；按住空格 + W 水平 2.19 格/秒；松开空格慢慢下沉；
     按住空格 + W 能游上一格高的岸；沉到水底贴着两格高的岸壁不会往上爬。

## 实测数据

`npx tsx tools/bench-v1.ts 4`（原版主世界，种子 42，8×8 区块，Node 22）：

| 项目 | v0 的做法 | v1 |
| --- | --- | --- |
| 方块数据 | 6.00 MB | 0.70 MB |
| 四边形 | 104,416 | 60,763 |
| 网格显存 | 11.95 MB | 3.01 MB |
| 每个区块生成（含网格） | 约 60 ms | 约 60 ms（时间主要花在密度函数上） |
| section 位数分布 | — | 0 位 1178 个，4 位 358 个 |

主线程重建网格：v0 整个区块约 33 ms；v1 最忙的一个 section（含展开邻域）约 1.6 ms。

浏览器（SwiftShader 软件渲染，视距 6，同一位置同一朝向）：

| | v0 | v1 |
| --- | --- | --- |
| 三角形 / 帧 | 236,008 | 62,800 |
| 绘制调用 | 111 | 195 |
| 帧时间中位数 | 81.9 ms | 59.8 ms |

## 留到以后

- 绘制调用变多（一个 section 一个网格），以后考虑合并缓冲区。
- 区块重新加载时，邻居区块边上的面按生成数据算，不看邻居的改动（v0 就有）。
- 草、树叶的颜色写死在纹理里，v4 按生物群系染色。
