# v10.1 开发日志

技术解析见 [../articles/v10.1-合成和工具.md](../articles/v10.1-合成和工具.md)。

## 目标

生存模式能自己“起步”：原木 → 木板 → 工作台 → 木镐 → 挖石头。合成用原版配方，工具照原版 1.21.4 的 `minecraft:tool` 组件。

## 过程

1. **数据**：`gen-items.py` 多读一个 jar（客户端、服务端都行，两个都有 `data/`）。
   - 数据报告 `items.json` 里 33 种物品有 `minecraft:tool`（6 种材质 × 镐斧锹锄剑 + 剪刀 + 重锤……），68 种有 `max_damage`。
     规则用到 13 个方块标签，展开成方块名写进 `tools.json`。
   - 配方：只要工作台的三种（有序 655、无序 277、换色 32），用到 26 个物品标签，展开写进 `recipes.json`。
     战利品表的 `match_tool` 还用到一个物品标签 `cluster_max_harvestables`，一起放进去。
   - 第一次生成的标签名是 `minecraft:minecraft:planks`：生成器里去掉 `#` 以后已经带了命名空间，又加了一次。
   - `itemList.json` 的格式（`["minecraft:acacia_boat", 1]`，逗号后有空格）保持和 v10 一样，免得整个文件都变。
2. **配方匹配**（`items/recipes.ts`）：图案和格子都先裁掉四周的空行空列；不对称的图案再比镜像（原料集合按 JSON 缓存，
   同一个原料是同一个 `Set`，所以“对称”可以用引用比较）。无序配方用增广路二分图匹配。
   测试写成“两块木板横着做不出东西”，结果做出了木质压力板 —— 是测试错了。
   加了一个全量测试：964 个配方每个按自己的摆法都做得出自己。
3. **合成格子**（`items/crafting.ts`）：点格子和点背包是同一套规则，把 `Inventory.click` 抽成 `clickSlot(slots, i, …)`。
   结果格、剩余物（牛奶桶 → 空桶）、Shift 连续合成、关界面时退回背包。
4. **工具**（`items/tools.ts`）：`miningSpeed`、`isCorrectTool` 照原版“第一条包含这个方块并且写了这一项的规则”；
   `damageTool` 照 `damage_per_block`。`ItemStack` 加了可选的 `damage`；背包的叠放判断改成 `sameItem`（物品和耐久都一样），
   捡起地上的东西、扔东西都改用 `addStack`，不然扔出去再捡回来的工具会变成全新的。
   剪刀挖羊毛我先算成 6 tick，其实 5 / 0.8 / 30 = 0.208，4.8 → 5 tick（0.25 秒），和 Wiki 一样。
5. **控制**：生存模式挖掘时按手上的物品算速度和“能不能掉”；挖掉以后要用工具的方块只有工具对才掉；工具掉耐久，坏了就没了。
   创造模式拿剑挖不动。右键工作台 → `Control.onOpenScreen` → UI 打开 3×3。
6. **界面**：背包上方加合成格子（2×2 或 3×3）、箭头和结果格；格子下面画耐久条；F3 的模式那一行加“手上: 速度 ×6 耐久 248/250”。
7. **浏览器里**（测试脚本模拟鼠标点击）：背包里原木 → 木板 → 工作台，放下工作台，右键打开，原木 → 木板 → 木棍 → 木镐，
   用木镐挖石头 1.14 秒（测试脚本自己的延迟也在里面），掉圆石，木镐耐久 57/59。
   中途遇到一个测试脚本的问题：关界面时 `lock()` 在无头浏览器里真的拿到了鼠标锁定，下一次鼠标事件带着一大段位移把视角甩开了，准星没指着石头。
   脚本里关界面后先 `exitPointerLock` 再假装锁定。

## 测试

`tests/crafting.test.ts`（10 个）：配方数量、每个配方都做得出自己、无序配方（各种原木 → 木板）、有序配方（木棍挪位置、木镐、弓和斧头的镜像、
多一样东西就不行）、换色配方、合成格子（结果格、剩余物、Shift 连续合成、关界面）、工具速度和对不对（七种镐挖石头的 tick 数、
木镐 / 石镐挖铁矿、斧头、铲子、剑、剪刀）、耐久（木镐 59 次、剑 2 点、硬度 0 不掉、创造模式拿剑）、背包 Shift + 点、
战利品表的 match_tool（剪刀剪树叶和草、紫水晶簇）。

全部测试：150 个通过。
