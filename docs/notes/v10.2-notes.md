## 性能：先量，再改

写了 `tools/bench-gen.ts`：从中心往外生成半径 4 的 81 个区块，分别计时原型、装饰和其余部分。

第一次结果（v10.1，单个 ChunkSource）：

```
生成（generateChunk）  平均 608.1 ms/区块
  原型（地形+地表+雕刻器）83.8 ms × 398 个
  装饰（地物）          70.5 ms × 216 个
  其余（拼邻居、颜色、压缩）8.0 ms/区块
光照 + 网格（meshChunk） 平均 45.2 ms/区块
```

81 个区块算了 398 次原型。半径 4 的区块要用到的原型最多是半径 8（17×17 = 289 个），多出来的是 LRU（160 个）挤掉以后又重算的。

CPU 采样（`node --cpu-prof`，半径 3）：

| 自身耗时 | 函数 |
| --- | --- |
| 12.8% | `Aquifer.computeSubstance` |
| 8.1% | `Climate.find`（查气候参数表） |
| 8.0% | `DensityFunction.compute` |
| 6.9% | `NoiseChunk.compute` |
| 5.3% | `ImprovedNoise.sampleAndLerp` |
| 5.0% | 垃圾回收 |

按调用链算，查生物群系（`getBiome` → `noiseBiome` → `Climate.find`）一共约 18%，含水层约 16%。这两样以后可以优化，
但比它们大得多的是结构问题：

- 游戏里有 3 个 Worker，每个有自己的 ChunkSource。区块按 4×4 的装饰区域固定分给某个 Worker（v5 的 `regionAffinity`）
- 一个区块要用周围 3×3 的原型和装饰。区域边上的区块，邻居属于别的 Worker，于是同一个原型在两三个 Worker 里各算一遍
- 模拟 3 个 Worker（`--workers=3`）：81 个区块一共算了 **601** 个原型、**370** 个装饰

## 改法：三段任务 + 主线程调度

- 原型、装饰、组装各是一个 Worker 任务（`worker/tasks.ts`）
- 主线程 `ChunkGenerator`（`terrain/generator.ts`）保存算好的原型和装饰，按依赖安排任务：依赖都好了才排队，排队按离玩家的距离
- Worker 收到任务时，把发来的原型、装饰放进 ChunkSource 的缓存（新加的 `putProto` / `putDecoration`），再调用原来的 `proto()` / `decoration()` / `generateChunk()`。
  它们在缓存里找到现成的就不会再算，所以计算代码一行没改，结果和以前一样
- 装饰的依赖（同一区域里排在前面、2 个区块以内的装饰）原来写在 `decoration()` 的循环里，抽成 `decorationDeps()` 给调度器用

### 测试怎么保证“一样”

`tests/generator.test.ts`：

1. 用三段任务生成 6 个区块（跨区域边界的、区域中间的、负坐标的），和另一个 Worldgen 直接 `generateChunk` 的结果比方块、流体更新、颜色，逐格相同。主世界、下界、demo 地形各一组
2. 依赖要全：如果调度器漏发了某个原型，Worker 会自己悄悄算出来，结果照样对，测试就发现不了。所以测试里把“缓存里没有还去算原型”改成报错。
   故意把 `decorationDeps` 改成返回空，测试报“任务缺少原型 -4,-4”，说明这个检查有效

### 调度器踩的坑

- 优先级：同一个原型可能先被远处的区块要、后被近处的区块要，要把排着的任务提前。一开始想在入队时记住“这个任务属于哪个缓存项”，
  但装饰的任务是依赖好了以后在 `then` 里才入队的，那时已经对不上了。改成任务直接拿着缓存项的引用，排序时读它当前的优先级
- 换种子：排着的任务作废（`epoch`），作废的区块不再打“生成失败”的错误日志

## 结果

Node，种子 42，半径 4（81 个区块），单线程依次算（总时间 = 总 CPU 时间）：

| | 原型 | 装饰 | 总时间 |
| --- | --- | --- | --- |
| v10.1，1 个 Worker | 398 | 216 | 54.1 秒 |
| v10.1，3 个 Worker（游戏里的情况） | 601 | 370 | 79.6 秒 |
| v10.2 | 286 | 216 | 45.4 秒 |

| | v10.1 | v10.2 |
| --- | --- | --- |
| 出生点可以开始玩 | 36 秒 | 23 秒 |
| 177 个区块全部加载完 | 约 160 秒 | 约 90 秒 |

F3 最后显示：原型 370 · 装饰 286 · 组装 177，中间结果约 80 MB。

## 在这边验证时遇到的环境问题（不影响游戏）

- 这边不能装 npm 包，用本机的 tsx 跑测试，用 tsx 自带的 esbuild 打包，自己模拟了 Vite 的 `import.meta.glob` 和 `?worker`
- 模拟的 glob 一开始把 `**` 转成正则时被后一步替换破坏，子目录里的文件没匹配上（“找不到密度函数 overworld/caves/entrances”）
- 3 个 Worker 同时 fetch 约 2800 个 JSON，Chrome 报 `ERR_INSUFFICIENT_RESOURCES`。真正的 Vite 构建会把 JSON 打进包里，不会这样；测试打包加了并发上限
