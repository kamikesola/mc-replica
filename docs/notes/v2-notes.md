# v2 开发日志

技术解析见 [../articles/v2-原版物理与手感.md](../articles/v2-原版物理与手感.md)。

## 目标

- 物理和帧率无关：每秒 20 tick，画面插值
- 走 / 跑 / 潜行 / 跳 / 飞 / 游泳的数值与原版一致，有测试
- 潜行不会掉下边缘；能钻 1.5 格的缝
- 原版的“手感”：惯性、空中控制弱、疾跑跳、视角摇晃、疾跑视野

## 过程

1. **先算 v1 的问题**：v1 每帧积分，跳跃高度随帧率变化（20 帧 1.038 格，144 帧 1.221 格）。
   这也解释了 v1.1 时水面的抖动：每帧在两套公式之间切换。
2. **碰撞重写**（`physics.ts`）：从“移动后退回”改成原版的“按轴裁剪位移”。
   碰撞形状改成 `ShapeFn` 返回盒子数组，为 v7 的台阶、半砖留好接口。
   抬步照原版 `collectCandidateStepUpHeights` 的思路：候选高度是挡路盒子的顶面。
3. **移动重写**（`movement.ts`）：按 LocalPlayer.aiStep → LivingEntity.aiStep → travel 的顺序写一个 `tickPlayer()`，
   不依赖 three 和 DOM，Node 里直接测。
   - 第一次跑测试：走 / 跑 / 潜行 / 跳跃高度 / 下落速度一次就对上了。
   - “疾跑跳比疾跑远”这条断言最初写成“多 0.3 格”，失败（只多 0.26）。改成测连续疾跑跳的平均速度，
     结果 7.127，正好是原版的公认值，比原来的断言有说服力得多。
   - 飞行上升的断言最初测的是速度（4.5 格/秒），不对：原版每 tick 先加 0.15 再移动，再 ×0.6，
     实际每 tick 位移是 0.375 格。改成测位移，7.5 格/秒。
   - 水面浮动的断言一开始把“从水底浮上来”也算进了起伏范围，加了预热。
4. **Control 重写**：时间累加器 + 插值；眼高平滑；视野倍数。
   - 视角摇晃要改相机的朝向，而 PointerLockControls 每次转视角是读相机当前朝向再加鼠标位移，
     摇晃会被累积进去。改成鼠标控制一个单独的 `head`，相机每帧从它复制再叠加摇晃。
5. **浏览器实测**：spawn 附近地形起伏，测速度时人直接走进了水里。改成在 y=150 铺一条石头跑道再测。
   软件渲染只有 5~7 帧，正好检验“和帧率无关”：速度、跳跃高度都对。
