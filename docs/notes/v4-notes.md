# v4 开发日志

技术解析见 [../articles/v4-生物群系与地表规则.md](../articles/v4-生物群系与地表规则.md)。

## 目标

- 每个位置的生物群系和原版一致（气候参数表 + BiomeManager 的抖动缩放）
- 去掉 v0~v3 的临时地表规则，改用 noise_settings 里原版的 `surface_rule`
- 草、树叶、水按生物群系染色，边界平滑过渡

## 过程

1. **气候参数表**：对照原版 `OverworldBiomeBuilder` 抄了 5 张 5×5 的表（MIDDLE / PLATEAU / SHATTERED 和两个变种）
   和所有切片函数，顺序和原版一致——查表遇到平局时取第一个，顺序不对结果就不对。主世界 7593 项，下界 5 项。
   查找没写 R 树，按原版的 `findValueBruteForce` 线性找，先用温度、湿度两维剪枝。
2. **BiomeManager**：种子先过一遍 SHA-256（`obfuscateSeed`），每个方块查 8 个 quart 角点、每个角点 3 次 LCG。
   第一版用 bigint，profile 里占 15%。改成两个 32 位数模拟 64 位乘法（16 位一段拆开，和 Long.js 一样），
   和 bigint 版本对拍 20000 组随机数全部一致，原版主世界每个区块 147 → 121 ms（打包后）。
3. **PerlinSimplexNoise**：群系温度（高处变冷、冰冻海洋）和沼泽草色用的。原版种子是写死的 1234 / 3456 / 2345。
   octave 下标 > 0 时原版要调用一次 3D simplex（只为推进随机数），这里没用到，就直接报错不支持。
4. **地表规则**：`SurfaceRules.ts` 把 JSON 解析成闭包，11 种条件；`SurfaceSystem.ts` 逐列从上往下走，
   恶地的陶瓦条纹（`generateBands`）、侵蚀恶地的石柱、冰冻海洋的冰山是原版硬编码的，照抄。
   “预估地表”（`above_preliminary_surface`）用 v3 写好的 `preliminarySurfaceLevel`，按 16 格的格子双线性插值。
5. **Java 对拍**：`tools/parity/Parity.java` 加了种子哈希、BiomeManager 选中的 quart、PerlinSimplex、量化、陶瓦条纹，
   `tests/parity.test.ts` 新增 4 组，全部一致。
6. **染色**：草 / 树叶 / 水的纹理改成灰度，alpha = 0 的像素表示“这里要乘颜色”。颜色不放进顶点（否则改群系要重建网格），
   放进三张 512×512 的颜色图，每个像素是一列，着色器按世界 x, z 取。每列颜色 = 周围 5×5 列平均（原版默认的过渡半径 2）。
   原版的 `grass.png` / `foliage.png` 颜色图归 Mojang 所有，不能放进仓库。第一版用三角形三个角插值，
   森林、针叶林的草色差了 14~16 个色阶。改成对 (t, 湿度×t) 的二次多项式，用 13 个已知群系颜色最小二乘拟合，
   这 13 个群系草色误差 ≤ 1、树叶 ≤ 2 个色阶——这么小的残差说明原版颜色图本身就很接近二次曲面。
7. **浏览器里的坑**：
   - 侵蚀恶地的石柱第一次截图是光秃秃的石头。原因：石柱是在“地表规则”之前放下去的，原版 `ProtoChunk.setBlockState`
     会同时更新高度图，所以规则从柱顶开始走；我这边高度图是提前算好的，没更新，规则从原来的地面开始走，
     柱子整根被跳过。`column.set` 里顺手更新高度图后，柱子上有了陶瓦条纹。
   - 你的 `datapacks/vanilla/worldgen/biome/` 里有 `pale_garden.json`。一开始我根据 `music` 字段的格式猜这份数据来自 1.21.5+，
     猜错了：和 1.21.4 服务端 jar 里的数据逐文件比较，noise / density_function / noise_settings / biome 完全相同，就是 1.21.4。
     1.21.4 起原版在高地变种表里加了苍白之园；现在的做法是数据包里有 `pale_garden` 就打开这一格。
8. **用原版报告核对**：用 1.21.4 服务端（SHA-1 `4707d00e…c001`）`--reports` 导出 `biome_parameters`，
   主世界 7593 项、下界 5 项**逐项一致**。不加苍白之园时正好有 20 项不同（都是 dark_forest → pale_garden），
   说明 1.21.1 的表和 1.21.4 只差这 20 项，凭记忆写的那一格位置也是对的。

## 实测数据

| 项目 | 数值 |
| --- | --- |
| 原版主世界每个区块生成（打包后，Node） | v3 约 102 ms → v4 约 121 ms |
| 一次没缓存的群系查找（6 个 router 字段 + 查表） | 约 140 µs |
| 种子 42，(0, 0) | y = 64 黑森林，y = 20 繁茂洞穴 |
| 种子 42，以 (0, 0) 为中心 6400×6400 格（y = 63） | 45 种群系，海洋 11.9%、森林 11.2%、平原 8.5% |
| 测试 | 72 个；有原版报告时全部通过，没有时跳过 2 个 |

## 怎么核对

1. **最准的办法**：用原版服务端导出 `biome_parameters` 报告，放进 `datapacks/reports/biome_parameters/`，
   `npm test` 会逐项比较（命令见 `datapacks/README.md`）。1.21.4 已核对通过。
2. 游戏里种子 42，F3 看 Biome 一行，和 demo 的 F3 比。BiomeManager 的抖动是和 Java 逐位对拍过的，
   所以连群系边界上的格子都应该一样；差一格就说明参数表或气候值有问题。

## 留到以后

- 原版颜色图（需要你自己客户端的 `grass.png` / `foliage.png`，可以像数据包一样放进被忽略的目录）；拟合以外的群系可能差几个色阶
- 群系查找的 R 树（现在线性找 + 剪枝，够用）
- 1.21.1 和 1.21.4 的差异：世界生成数据（噪声、密度函数、noise_settings 含地表规则）两版相同，群系表只差苍白之园；
  Java 代码层面（含水层、移动物理等）没有逐版对比过
