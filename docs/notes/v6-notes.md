# v6 开发日志

技术解析见 [../articles/v6-光照与昼夜.md](../articles/v6-光照与昼夜.md)。

## 目标

到 v5.2 为止所有方块都是“满亮度”：洞穴和地表一样亮，没有白天黑夜。v6 要做：

- 光照引擎：天空光、方块光，和原版存档里存的 SkyLight / BlockLight 逐格一致
- 渲染：原版的平滑光照（AO 加上亮度插值）、光照贴图（lightmap）
- 挖放方块、流体流动时，光照增量更新
- 昼夜：时间流逝，天空和雾的颜色、日出日落、太阳、月亮、星星

## 过程

1. **光照属性从原版 jar 导出**：写了一个很短的 Java 程序（`tools/vanilla/LightDump.java`），直接调用原版服务端的类
   （混淆名：`ab.a()` 检测版本、`akx.a()` 初始化注册表、`mb.e` 是方块注册表），打印每个方块状态的 `lightBlock` 和 `lightEmission`。
   `gen-light.py` 编译运行它，给我们的 218 种方块各挑一个状态写进 `src/terrain/light/lightProps.json`（完整的 27866 个状态留给核对工具）。
   原版 jar 带签名，和我们放在默认包里的类会冲突，先去掉签名再用。
2. **读字节码确认算法**：`esk` = ChunkSkyLightSources（每列从上往下找第一个挡光的方块）、`est` = SkyLightEngine、
   `esr` = LightEngine（`b(dwy)` 就是 `max(1, lightBlock)`）。规则：
   - 每走一格亮度减 `max(1, 目标的 lightBlock)`
   - 天空光源：每列第一个 `lightBlock ≠ 0` 的方块（或底面挡光的方块）以上全是 15
   - 形状遮挡：只有 `useShapeForLightOcclusion` 的方块才看形状。我们用到的只有雪层、下半台阶、幽匿感测体 / 尖啸体，都是“底面完整”
3. **引擎**（`light/LightEngine.ts`）：按亮度分桶的广度优先，3×3 个区块一起算，中心区块加外面一圈是精确值
   （光最多走 15 格）。区块光照存成 18×18 列，网格生成直接用。
4. **对照工具** `diff-light.ts`：
   - `--vanilla-blocks`：拿原版存档里的方块（精确到状态）算光照，只检验引擎
   - 默认：拿我们生成的方块算，端到端
   - 原版自己的数据也会“没算完”：保存时有些光照更新还在队列里，存档里出现过石头里天空光 15 的整片区域。
     工具检查每格是不是满足“亮度 = max(光源, 邻居 − 代价)”，不满足的标出来，整个区块不计入
5. **第一次对照**：方块光 100%；天空光只有一处不对——树叶上的雪层下面原版暗 1 级。原因是雪层的底面挡光，加上之后引擎逐格一致。
6. **增量更新**（`light/LightUpdater.ts`）：先熄灭再点亮（原版 propagateDecrease / propagateIncrease），天空光还要处理光源段的变化。
   测试里随机挖放 300 次，每次都和整块重算比较，全部一致。
7. **加载流程改成两步**：Worker 先生成方块；周围 8 个区块都生成好之后再算“光照 + 网格”，算完才显示。所以生成范围是视距 + 1。
   主线程给每个区块留一份不压缩的方块（约 100 KB），算光照时把 3×3 份发给 Worker。
   算的时候方块变了（挖放、流体）就作废重算（每个区块有个版本号）。
8. **平滑光照**（mesher）：完整方块的面，每个角取 4 格亮度之和（中心、两边、斜角；亮度 0 的换成中心的，两边都挡光时斜角用第一边），
   存进顶点（0..60，保留 1/4 级精度）。合并面的条件多了“四个角的亮度一样”。AO 改成原版的 0.4 / 0.6 / 0.8 / 1.0。
   发光的方块、十字形植物、流体用 flat 光照；十字形植物、藤蔓不按方向变暗（原版模型里 `"shade": false`）；岩浆块总是最亮（emissiveRendering）。
9. **光照贴图**（`sky/formulas.ts`）：照抄 1.21.4 的 `lightmap.fsh` 和 `LightTexture`。顶点着色器里采样（原版也是逐顶点），
   线性过滤、坐标 = 亮度 / 16——所以亮度 15 实际取的是第 14、15 格的平均，原版就是这样。
10. **昼夜**：`timeOfDay`、`skyDarken`、天空色、雾色（含朝太阳方向混入日出色、往天空色靠）、日出日落扇形、太阳月亮星星（种子 10842，1500 个点留下 780 个）。
    群系的 `sky_color` / `fog_color` 由 Worker 按原版 `CubicSampler`（6×6×6 高斯核）平均。
    天空画在单独的场景里，先画天空、清深度再画地形。雾改成原版的圆柱形雾、范围按原版（视距最后 1/10）。
11. **F3**：`Client Light: 15 (15 sky, 0 block)`、时间。菜单里加了时间滑块、昼夜循环开关、亮度（昏暗 / 默认 / 明亮）。

## 实测数据

| 项目 | 天空光 | 方块光 |
| --- | --- | --- |
| bare 存档（我们生成的方块和原版逐格一致），主世界 36 个区块，去掉原版没算完的 4 个 | 100% | 100% |
| bare 存档，下界、末地 | 100% | 100% |
| 完整存档 + 原版的方块（只检验引擎），主世界 160 个区块，去掉原版没算完的 41 个 | 99.994%（剩下的全是原版更亮，即原版没算完的区域旁边） | 100% |
| 完整存档 + 原版的方块，下界、末地 | 100% | 100% |
| 完整存档 + 我们生成的方块（端到端），主世界 | 99.82% | 99.44% |
| 完整存档 + 我们生成的方块，下界、末地 | 100% | 99.06% |

端到端的差别来自方块本身：洞穴藤蔓有没有发光的浆果、海泡菜的个数（方块状态，v7）、树的位置（生成顺序）、
原版存档里流过的岩浆（保存前服务端跑了一分钟）。

| 性能（Node，一个区块） | |
| --- | --- |
| 光照（3×3 区块） | 主世界约 15 ms、下界约 4 ms |
| 光照 + 24 个 section 的网格 | 主世界约 50 ms、下界约 40 ms |
| 挖放一个方块的增量更新（浏览器） | 平均 2 ms |
| 测试 | 91 个，全部通过（新增 tests/light.test.ts 10 个） |
