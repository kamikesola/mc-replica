# v7.1 开发日志

技术解析见 [../articles/v7.1-方块模型.md](../articles/v7.1-方块模型.md)。

## 目标

v7 有了方块状态，但画法还是 v1 的：完整方块 + 十字 + 薄片，纹理是程序画的。v7.1 要做：

- 读原版资源包（blockstates、models/block、textures/block），不进 git
- 烘焙：状态 → 四边形，和原版 ModelBakery / FaceBakery 一样处理 parent、旋转、uvlock、cullface、tintindex
- 网格：模型的整面照样贪婪合并，其他面逐个输出；光照、遮挡、染色按原版
- 没有资源包时和 v7 一样

## 过程

1. **资源包**：从客户端 jar 拷三个目录（`tools/vanilla/extract-assets.py`，4349 个文件，18 MB）。浏览器里用
   `import.meta.glob` 懒加载，只读用到的方块状态文件，再按引用和 parent 读模型；纹理只读用到的 308 张。
2. **烘焙**（`src/terrain/models/bakery.ts`）：照抄 FaceInfo 的顶点顺序、BlockFaceUV 的 rotation 轮换、默认 uv 的公式、
   元素旋转的 rescale（1/cos − 1）、BlockModelRotation（rotateYXZ(−y, −x, 0)）。cullface 跟着旋转；
   朝向按旋转后的法线取最近的方向（FaceBakery.calculateFacing）。uvlock 用“按转完的位置重新取默认 uv”代替原版的 recomputeUVs
   （对没写 uv 的面结果一样）。结果是普通对象，2372 个状态共用约 900 种面，主线程 120 ms。
3. **整面的纹理映射**：解 uv = M·D + c，M 只能是 90° 旋转 / 镜像。验证了 4 个顶点都满足才算整面。
   横放的原木、石头的镜像候选都能合并；草方块侧面（两层）、雪层、花草都不算。
4. **顶点格式**：加 `uv`（Int16×2），`info` 改 Uint16（纹理层超过 255；AO 存 0..255 以便插值）。
   着色器不再按位置算 uv。顺手把底面的纹理方向改成原版的（v 沿 -z）。
5. **随机候选**：先查了一下 1.21.4 的 WeightedBakedModel 用的是哪种挑法 —— 在客户端 jar 里找
   “`Math.abs((int) nextLong())`” 这个字节码模式，没有找到，所以按 `nextInt(总权重)`（SimpleWeightedRandomList.getRandomValue 的挑法）实现。这一点没有和原版画面逐格核对过。
   multipart：先 nextLong，每个部分重新 setSeed。
6. **光照**：把 v6 平滑光照里算 4 个角的那段抽成 `cornerData`，贪婪面和模型面共用。模型面不在边界上时“中心”取方块自己；
   每个顶点按位置双线性插值。
7. **遮挡**：`OCCLUDES` 代替 `SOLID` 判断面要不要画。第一次跑时森林里看到了“虚空”—— 树叶挡住了旁边的泥土，加上 noOcclusion 的列表。
   测试里“树叶挨着石头”时，树叶朝石头那面不画、石头朝树叶那面要画，11 个面，一开始测试写成了 12，是测试错了。
8. **含水的植物**：海草、海带、珊瑚的状态一直含水，一开始按“是流体就跳过”把它们也跳过了，改成只跳过水和岩浆本身。
9. **纹理**：纹理数组 = 程序画的纹理 + 资源包纹理。资源包纹理的名字一开始带着 `textures/` 前缀，查不到，满屏紫黑格子。
10. **性能**：网格生成先看邻居挡不挡，挡住了就不去挑候选（挑候选要算 BigInt 的随机数）。
