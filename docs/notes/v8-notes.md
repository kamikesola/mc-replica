# v8 开发日志

技术解析见 [../articles/v8-存档.md](../articles/v8-存档.md)。

## 目标

- 玩家改过的方块、玩家位置、时间存进浏览器（IndexedDB），刷新页面不丢
- 存档列表：新建、进入、删除
- 导入原版存档：读 level.dat、区域文件（.mca），没存的区块按存档的种子生成

## 过程

1. **只存改动**：v0 起 `Terrain.edits` 就记着玩家改过的方块。存的时候按区块写成调色板（状态用字符串），
   这样以后状态编号变了也能读。`tests/save.test.ts` 里把所有 2372 个状态编码再解码，全部还原。
2. **IndexedDB**（`src/save/store.ts`）：三张表 worlds / chunks / files，键 `世界id|...`，删除世界时按键的范围删。
   测试用同样接口的内存版（Node 里没有 IndexedDB）。
3. **NBT**（`src/save/nbt.ts`）：对照工具里的 Node 版换成 DataView。解压用 DecompressionStream（Node 22 也有）。
4. **区域文件**（`src/save/anvil.ts`）：一开始解出来三分之一的方块是空气 —— 写 section 的起始位置时乘成了 4096（应该是 16 × 256），
   第 0 段正好对，后面全错。修好后，9 个区块和 Node 版的读取工具逐格一致。
   按位解码时每个 long 拆成两个 32 位数，不跨 32 位的直接取，跨的拼起来。
5. **Worker 异步**：解压是异步的，Worker 的处理函数改成可以返回 Promise。
6. **原版方块 → 我们的**（`src/save/blockMap.ts`）：先 `parseState`（带属性），不认识的按名字的规则找代替品，再不行当空气，都计数。
7. **出生**：存档里有玩家时直接传送过去，等脚下的区块点亮了再开始物理（不然会掉下去）；原版的服务端存档没有玩家，
   在出生点附近找落脚的地方（原来只在原点附近找）。
8. **测试存档**：`tools/vanilla/make-save-fixture.ts` 从原版服务端存档里剪出 level.dat 和 9 个区块（区域文件格式不变，80 KiB）。
9. **浏览器里验证**：在原版服务端里用命令（fill / setblock）在森林边的湖上盖了一间小屋，导入后看到了小屋；
   代替了 9 种方块（石砖、橡木台阶、玻璃板……），没有不认识的。保存 → 刷新：放的方块、玩家位置、飞行状态都在。

## 数字

- 原版存档的区块和我们按同一个种子生成的区块：5 个生物群系（森林、沼泽、桦木森林、平原、原始桦木森林）各一个区块，99.92% 一致
- 解码一个区块（解压 + NBT + 方块）：约 20~30 ms（Node）
- 一个新世界走一圈：几十个区块有改动，大部分是流体流动（含水层边上的水流进洞里），和原版一样也算改动
