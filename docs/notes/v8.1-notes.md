# v8.1 开发日志

技术解析见 [../articles/v8.1-原版全部方块.md](../articles/v8.1-原版全部方块.md)。

## 目标

v8 导入原版存档时，我们没有的方块只能换成代替品。v8.1 把原版 1.21.4 的全部方块加进来：属性、光照、碰撞箱、破坏时间、模型都用原版的。

## 过程

1. **导出**：新的 `tools/vanilla/BlockDump.java` 在 v6 的 LightDump 上加了碰撞箱和破坏时间。方法名不手查，用反射按签名列出候选，
   再用已知方块的值认出来（栅栏碰撞箱 1.5 高、一层雪没有碰撞箱；基岩破坏时间 -1、石头 1.5）。第一次跑就认对了。
   `gen-blocks.py` 一次写出方块名、属性、光照、碰撞箱、破坏时间，代替 `gen-states.py` 和 `gen-light.py`（这两个和 `LightDump.java` 删了）。
2. **编号**：手写的 234 种不动，其余 875 种按原版注册顺序接在后面。`StateRegistry.blockOf` 从 `Uint8Array` 改成 `Uint16Array`
   （方块数超过 256 了），几张按方块的表原来写死了 256 项，改成按方块数。
3. **按状态的数据换成原版顺序**：v7 的光照表按我们的状态顺序写，要在 TypeScript 里跑一遍才能生成。现在按原版顺序写（直接来自导出），
   加一个 `vanillaIndex` 换算。
4. **新方块的 BlockInfo**：实心 = 碰撞箱是完整方块；能不能挖 = 破坏时间 ≥ 0；没有资源包时的程序纹理和形状按名字、碰撞箱粗略地挑。
   已有方块的“实心”不变（比如箱子的碰撞箱不满一格，但 v5 起它就算实心，地形生成的对照测试依赖这个）。
5. **碰撞**：`Control` 的形状函数从“实心就是完整盒子”换成原版碰撞箱；放方块时检查的也换成要放的那个状态的碰撞箱。
6. **染色**：红石线（16 种信号强度）、南瓜梗 / 西瓜梗（8 个生长阶段）、已经结果的梗，原版 BlockColors 的公式。染色字段的 5 位正好用满（4..31）。
7. **测试里发现的保存 bug**：浏览器里“放方块 → 保存 → 刷新”这一步，v8 时偶尔通过、v8.1 时总是失败：
   启动变慢以后，手动保存总是撞上正在进行的自动保存，而 `save` 在这种情况下直接返回了上一次的 Promise，
   新的玩家位置和刚放的方块都没存进去。改成等上一次存完再存一次，并加了测试（两次保存重叠，第二次的内容要在）。
8. **模型**：资源包里全部方块都有模型，除了原版用方块实体渲染器画的（告示牌、床、旗帜、潜影盒、头颅、箱子、饰纹陶罐……）
   和看不见的（屏障、光源方块、结构空位）。墙和瓶子草作物有几个状态没有任何部分（比如四面都不连、也没有柱子的墙），原版也是什么都不画。

## 数字

- 原版 1095 种方块、27866 个状态；我们 1109 种（含流体的各个状态）、27816 个状态；320 种碰撞箱
- 用到的资源包纹理：308 → 998 张
- 烘焙全部模型 0.8 秒，`setModels` 0.15 秒，复制一份给 Worker 0.4 秒（Node 里测）
