# v9.1 开发日志

技术解析见 [../articles/v9.1-红石.md](../articles/v9.1-红石.md)。

## 目标

红石的基础部分：信号的强弱规则、红石线、拉杆、按钮、红石火把、中继器、红石灯、门 / 活板门 / 栅栏门、活塞。

## 过程

1. **信号查询**：照着原版 Level.getSignal / getDirectSignalTo / getBestNeighborSignal 写成 `signalAt`、`bestNeighborSignal`。
   方向参数的约定（“从收信号的一方指向发信号的一方”）一开始很容易写反，每种方块都对着原版代码核对了一遍：
   拉杆的强信号看 `getConnectedDirection`（地上的拉杆是 UP，因为收信号的是它下面那个方块，从下往上指向拉杆）。
2. **导体**：原版默认“碰撞箱是完整方块”就是导体，玻璃、树叶、红石块、侦测器、活塞等例外。用 v8.1 导出的碰撞箱 + 一个名字列表。
3. **红石线**：强度按 calculateTargetStrength，算的时候关掉红石线的强信号；形状按 getConnectingSide（爬墙看上面不是导体、
   旁边方块顶面坚固 —— 用 v9 的 STURDY）。形状更新放在 v9 的 `updateShape` 里，红石自己的 neighborChanged 里也一起更新
   （斜上斜下的线变化时，6 个邻居的形状更新覆盖不到）。
4. **队列和计划刻**：`Redstone` 类，`changed` 把曼哈顿距离 2 以内的格子放进队列，`process` 一个个 neighborChanged，
   `tick` 处理到期的计划刻。一次最多处理 20000 个，处理不完下次继续（防止意外的环路卡死）。
5. **接到游戏里**：`Terrain.updateBlock` = 写入 + 形状更新（placement.neighborUpdates）+ 红石；`Control` 挖、放、用都走它。
   右键先问 `useRedstone`（拉杆、按钮、中继器），再问 v9 的 `useBlock`（门）。
6. **测试里的两个笔误**：拉杆放的位置写错了（点到被石头占着的格子，放不下）。
7. **浏览器里**：天上的草地上，拉杆 → 5 格红石线 → 灯；另一个拉杆 → 2 格红石线 → 活塞推泥土。
   第一次放活塞时它朝上 —— 因为玩家低头看着地面放的，原版也是这样（活塞朝视线的反方向，包括上下）。改成平视着点方块的侧面放。
   线中间旁边那盏灯不亮，对照原版规则是对的（直线只给两头充能）。

## 测试

`tests/redstone.test.ts`（8 个）：16 格红石线的强度、形状（十字、直线、爬墙）、红石灯的延迟、火把非门、中继器（延迟、放大、调延迟）、
强充能穿过方块和“红石线指着的方块不能给另一根线充能”、活塞（推、推碎、收回、粘性、推不动黑曜石）、按钮开门再自动关。

全部测试：133 个通过。
